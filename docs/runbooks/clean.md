# WORKSTATION CLEAN

`ws clean` удаляет то, чем ничто не пользуется: старые поколения
home-manager и пути Nix store без корней, образы Podman без контейнеров,
рантаймы Flatpak без приложений. Сначала план, потом выбор областей и
подтверждение. Код — `libexec/ws-clean`.

```sh
ws clean                  # план всех областей, выбор, подтверждение
ws clean --dry-run        # только план, ничего не удаляет
ws clean nix podman       # только эти области
ws clean --keep-days 7    # nix: оставить поколения моложе 7 дней
ws clean --yes podman     # без вопросов; области — по имени
```

## Области

| Область | Что удаляет | Чем |
|---|---|---|
| `nix` | поколения home-manager старше `--keep-days` (30), кроме текущего; затем пути store, которые не держит ни один корень | `nix-env --delete-generations` с номерами из плана, `nix-store --gc` |
| `podman` | образы, которые не использует ни один контейнер, в том числе остановленный | `podman rmi ID` по плану |
| `flatpak` | рантаймы user-установки, не нужные ни одному приложению | `flatpak uninstall --user --unused` (как `ws flatpak cleanup`) |

- `nix`: поколения checkpoints держат свои GC roots (ws help rebuild,
  `ws checkpoint`), их пути остаются в store, даже если ссылка поколения
  удалена. `--keep-days 0` оставляет только текущее поколение и
  checkpoints. `nix-collect-garbage -d` не используется: он удаляет
  поколения всех профилей. Оценка места — размер NAR, на диске со
  сжатием меньше.
- `podman`: контейнеры, volumes и rootfs боксов Distrobox не трогаются.
  Образ без контейнера может понадобиться снова (бокс, который ещё не
  создан, тестовый образ) — его скачают или соберут заново. Размеры
  включают общие слои: сумма больше того, что освободится.
- `flatpak`: у flatpak нет пробного запуска; план — его список, на
  вопрос которого `ws clean` отвечает «нет».

Чего `ws clean` не трогает никогда: checkpoints, снимки Btrfs и
Timeshift, backup, VM, Steam, префиксы Wine, контейнеры, volumes,
`~/.cache`.

## Как идёт

1. План по каждой области: что удалится и сколько места (неизвестное —
   `?`). Области, которых на машине нет, названы (`not here`). Пока
   область считается, в терминале видно `== nix: planning…`; план `nix`
   занимает секунды (корни GC и их замыкания), дольше под нагрузкой.
2. Выбор областей (Gum, все отмечены), затем подтверждение — по
   умолчанию «нет». `--dry-run` останавливается после плана.
3. Перед каждой областью план строится заново. Изменился — показывается
   и спрашивается снова; с `--yes` такая область пропускается (`SKIP`).
4. Итог по каждой области: `OK`, `FAIL` или `SKIP`. Код выхода 1, если
   есть `FAIL`.

Без терминала `ws clean` удаляет только с `--yes` и областями по имени;
`--yes` без областей — отказ.
